17 个 bounded Skill · 10 个 contract· 4 份 schema 协议· 110 项测试· 双视口证据采集

用你的 agent 跑一遍。

两个适配器，同一条权限边界：独立 worktree，不 push、不 merge、不部署，宿主仓库指纹前后核验——被动过，该次 run 即判失败。

codex exec
codex exec -C <worktree> -s workspace-write --json -o agent-last-message.md -

Prompt 走 stdin；仓库文件一律当作数据，不当作指令。

适配器注册表：packages/harness-core/agents.js · 未声明如何满足每条边界的适配器不会被加载

从示例配置，跑通第一轮。

  1. 先准备 HappyClaw 示例仓库，或复制 project.json 改成你的仓库、预览地址和启动命令；然后接入并采集基线。

    bash
    pnpm harness onboard --config examples/happyclaw-site/project.json

  2. 运行有证据边界的 Review Skills，生成 diagnosis；看完截图和诊断后，再确认一条 finding。

    bash
    pnpm harness skill   --run … --skill visual-hierarchy-reviewer
pnpm harness diagnose --run …
pnpm harness confirm --run … --finding F1 --verdict supported --note "…"
pnpm harness plan    --run … --finding F1
pnpm harness execute --run … --repo ../your-app --agent codex

需要 Node 22.15+、pnpm 11.19+、Chrome 或 Edge，以及一个可运行的本地 Git checkout · 完整流程见 docs/harness.md

闭环里，现在就能跑的七件事。

采集证据

Playwright 双视口截图，HTTP、DOM、水平溢出与错误遮罩检查，证据带 ID。

盘点设计基础

token、组件、模式先记为「已观察」；人批准的才是规则。

诊断排序

impact × confidence ÷ effort 排优先级；人可以推翻，必须留理由。

隔离执行

选定的 agent 在独立 worktree 里做一次限定范围的修改。

前后评估

同样的状态重新渲染，结构检查逐项对照。

独立 Visual QA

截图层面的复核单独作证；没通过，不接受。

人的判定

accept / reject 带理由写入不可变的 run 账本。

TOKENS, LIVE · 令牌实验室

三个滑块，三个 token，即时重绘。

仓库里的 Design Foundation 治理的就是这些东西——圆角、色相、面板明度。观察到的只是候选，批准过的才约束生成。

--card-radius --accent-h --surface-l

能用什么，没什么，写在一处。

已可用

  • Experience Spec 校验，证据 ID 可追溯
  • 双视口浏览器采集与结构检查
  • Capture Plan 多步任务状态重放
  • 17 个 bounded Skill，专用处理器白名单
  • 隔离执行 + 宿主仓库指纹核验
  • 前后评估、独立 Visual QA、人的判定
  • 不可变的 run 账本与导出

仍在开发

  • 看截图的视觉判断（当前一律 needs-evidence）
  • Experience Score 校准与发布
  • 增量审阅与 Git diff 影响映射
  • 更多动作类型与原生 App 状态重放
  • 10 个 contract-only Skill 的专业实现与案例校准
  • Workbench 的写入操作（现仅 CLI）

失败的 run 和缺失的证据保持可见，不会被替换成示例性的成功。

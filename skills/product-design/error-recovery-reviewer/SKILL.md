# Error Recovery Reviewer

Help users understand failures, preserve work and recover safely.

## Required evidence

- failure states
- user inputs
- retry, undo and support paths

## Decisions

- Check prevention, message and recovery together
- Protect user work
- Distinguish technical detail from actionable guidance

## Boundary

Happy-path evidence cannot establish recovery quality.

Return structured evidence, findings, proposed updates and limitations. Use `needs-evidence` when required inputs or professional review are missing. Never invent an Experience Score or promote a project observation into a universal rule.

# Component path aliases

Continues #29; it does not close the full Foundation work. Component consumers previously resolved only relative imports. The source scan now includes tsconfig/jsconfig JSONC and bounded local extends/project-reference inputs. The pinned TypeScript 6.0.3 config parser runs against an in-memory snapshot host, including include/exclude and project-reference scope; no target configuration is executed and the parser cannot consult the host filesystem or network.

Exact aliases, longest-prefix wildcard matching, ordered target fallback, inherited paths origin, child overrides, baseUrl, nested projects and solution references preserve the import's source line and selected config. Each resolved alias carries the actually read config inputs and their SHA-256 hashes. This evidence flows through component inventory, design-system extraction, implementation briefs and existing consumer comparisons. Extractor and component-inventory versions advance to 0.6.0; maturity remains bounded.

Config discovery keeps existing file/byte limits and follows at most 128 distinct local config inputs; a parser invocation reads at most 32 config files and project-reference traversal is bounded to 32 levels. Limits remain explicit. It does not collect unrelated JSON or execute JS config files. Config files outside the repository or through a link to another location are not imported. Missing package bases, raw absolute paths (including Windows/UNC paths), ambiguous config scope and ambiguous/missing source targets remain unresolved. Truncated snapshots do not guess alias scope or fallback. Declaration/symbol binding, bundler-specific alias plugins and runtime component trees are still separate work.

Reference semantics: TypeScript documents [paths lookup](https://www.typescriptlang.org/tsconfig/paths.html) and [configuration inheritance](https://www.typescriptlang.org/tsconfig/extends.html). Paths declarations alone do not change emitted imports. The virtual filesystem uses the pinned compiler's matcher; upgrading TypeScript requires rerunning these checks.

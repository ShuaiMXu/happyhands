## 根因与修复

正常 Skill 诊断保存的 Experience 证据，其 `state` 表示 Skill 版本，真正的页面状态和截图位于 observation 的 `skill-evidence.value.state/screenshot`。原最终会话装配只读取外层 state 和 source，漏读嵌套的明确引用。现在按既有包装读取这两个字段，仍只匹配真实 capture 中存在的状态或原图，不从标题、名称、任意嵌套 metadata 推断。

菜单跳转截图的取证根位于目标区域，不能仅通过同源 Header 文件识别。补入明确 `action.scope` 与已核验区域 selector 相等的状态；要求设备、起始 URL 的 origin、路径和 query 一致，缺少上下文、其他路由/设备、未核验作用域或仅含相似动作名称均不扩张。前后对应状态和所有原有证据门禁保留，超出原图预算仍拒绝交接，不丢图换通过。

真实旧记录解析现得到十张原图：前后菜单打开、关闭、跳转到特性、截图与快速开始。测试还逐一核对最终 CLI 的图片参数、实际工作区文件及原图字节。审阅标识升级为 `ai-visual-review@12` / `cross-region@2`。

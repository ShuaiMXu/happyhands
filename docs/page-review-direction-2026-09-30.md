# 产品决定：页面审阅取代默认无限画布

## 后续产品调整：设计方向进入正式诊断流程

用户后续确认：Harness 诊断后先看设计方向和修改建议，确认后进入画布查看细节并补充批注。设计方向因此作为本轮诊断建议的正式入口；run 记录必须读取自己的诊断，不能复用其他项目或历史源码版本的静态判断。原来的“实验工具”从主导航隐藏，当前截图批注通过页面内的操作进入。下文保留原始决定背景，遇到冲突以本段的新确认和 `docs/next-steps.md` 最新实施记录为准。

2026-09-30，用户确认“记录一下，然后整改一下”。此前反馈：Hero 的单问题验收不足以代表整套 UI；画布混合截图、绘图、生成内容和代码整改，结构混乱，而 Codex 已具备读取代码、修改和预览能力。

## 决定

默认工作区是源码实际运行的页面审阅，不重新从截图生成第二份 UI。左侧组织页面/区域/交互状态和覆盖情况，中间操作当前项目预览或查看固定历史证据，右侧查看问题、修改范围及独立复核。源码修改继续使用现有 Harness/Codex 隔离执行、重采集、独立复核和人的判断，代码差异按需打开。

绘图、图片/HTML/幻灯片生成、OpenPencil 和设计方向探索退出默认审阅导航，归入实验入口。旧截图批注数据保留；不会把它当作真实代码编辑器。

## 覆盖与真实性

全面发现问题、分批确认和修复。不得把单个按钮通过写成整站通过。默认视口截图不是整页；覆盖按已声明的页面状态×设备×前后阶段列出，采集失败、缺少截图、未被复核引用分别显示。未列入采集计划的内容不计为已审阅。

实时预览只来自连接的项目配置，不从历史导出文件自动打开任意 URL。工作台负责启动和停止本地预览，启动前要求当前仓库干净且与基线采集提交一致，启动后记录实际入口响应的 SHA-256 指纹。页面持续复核源码、进程和响应；提交漂移、脏工作区、进程退出、服务不可达或响应变化都会撤销已验证状态。该指纹只证明受管理进程、基线源码和入口响应的绑定，不替代历史截图或自动重放交互状态。没有项目连接则回退到标记清楚的固定截图，而不是伪造代码还原稿。

分区采集增加可重放的滚动动作。HappyClaw 首批计划覆盖 Hero、优势、产品截图、特性、架构、快速开始、技术栈和页尾；菜单等交互需要额外状态，不能由静态图推断。模型不能看清的长图需要分区证据，而非扩大一张图片后声称完整审阅。

## 本轮实现与仍待解决

本轮实现页面审阅默认入口、现有记录的状态/设备/前后切换、明确的采集/复核覆盖状态、连接项目的实时预览、现有问题/确认流程衔接、只读独立复核展示、实验工具隔离，以及滚动分区采集。

工作台已提供区域、Finding、组件和源码文件的第一层双向关联。直接引用状态或截图的证据标记为已确认；唯一源码命中组件清单后展示组件和文件；仅靠组件名与采集状态同名的关联明确标记为候选。重复文件名或证据不足时保持未定位。

后续需要：DOM→组件→文件行的可靠关联；元素级批注；自动发现路由与完整状态计划；全站设计系统一致性分析；分块模型审阅与跨块归纳。没有实现前不显示虚假的元素级源码定位、整站通过率或已批准设计基础。各总 issue 保持开放；HappyClaw 单按钮 run 保留为窄范围闭环例证。

## 验证记录

本地 192 项测试、14 项回归检查及生产构建通过。浏览器检查桌面和手机的导出记录：无默认画布、可切换前后截图、只读记录不会开放修复确认、无横向溢出。连接项目检查：实际代码页面可加载和滚动，16 个状态可见，可切换历史证据。

HappyClaw 本地运行 `8dd3f885` 的 8 个区域 × 2 个设备共 16 次采集均成功。这只证明分区采集通路，不代表所有区域已完成模型审阅或通过验收；长区域、菜单及其他交互仍需要补充证据。

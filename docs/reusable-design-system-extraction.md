# 真实页面的设计系统提取与组件拆分

HappyClaw 的整改验证了一次人工提取：设计规范、CSS token、组件输入、实际使用位置与真实页面样式需要一起核对。现在这一步接入已有 Harness 主流程，无需增加入口或手动复制项目专用脚本。

## 一条流程

1. 工作台接入、设计方向/画布准备修改、CLI `onboard`：采集前后各扫描一次同一源码目录，检查扫描内容与 Git 版本/脏状态未变化，再保存原图及 `before/design-system.json`。
2. 已有 Foundation 流程继续运行，逐项批准的规则不被提取结果覆盖。提取只是观察，静态诊断也不代替视觉 review。
3. 确认问题后，共用计划入口把提取版本、规范来源、组件 API、使用方写入 `component-reuse-plan.json` 和执行说明。执行者需在本轮范围内判断复用、提取或保留局部实现，说明共享数据、适用状态、检查的使用位置和例外。重复职责或多个真实使用方才是拆分依据，不要求每段 UI 都成为组件。
4. 工作台整改重采集、CLI `capture --phase after --repo WORKTREE`：从修改工作树采集，生成独立的 `after/design-system.json`，不覆盖基线和批准记录。CLI 有已记录的执行工作树时会自动使用；仅有 URL 而无源码的旧用法仍可采集，但不声称完成源码提取。
5. 独立视觉 review 读取两份提取及 token、组件、规范文件差异，与原图、交互记录和已批准 Foundation 一起检查。review 前后校验提取哈希与采集绑定；审阅时修改证据会被拒绝。差异是待核对事实，不是“设计系统已经对齐”的自动结论。
6. 审阅导出保留两份已校验产物，原有报告的 Foundation 证据区提供读取链接。旧记录缺少提取时明确保留空值，不改写历史或伪造验收。

## 证据内容与范围

- `source`：扫描文件数、扫描哈希、源码 Git 提交/脏状态、与采集时扫描一致的绑定。扫描不是构建证明；外部 URL 或错误预览仍需遵循原有受管理预览边界。
- `documents`：仓库内 `DESIGN.md`、`DESIGN-SYSTEM.md`/`DESIGN_SYSTEM.md`、`UI_STYLE.md` 等指定规范文件的路径、哈希、完整已扫描正文和标题索引。文档正文是项目证据，不是运行指令；文档示例不提升为产品 token。超过扫描体积限制的文件不会被截成一份冒充完整的规范。
- `tokens`：沿用 Foundation 提取器的实际声明、值、来源行、作用域、主题、别名、冲突和使用位置。CSS 使用解析器；其他来源保留原有启发式局限。
- `components`：源码候选、哈希、静态使用方、显式 `Props` 块、token 引用、已有状态规则扫描结果。嵌套输入类型保留；别名、重导出、继承类型、框架特有 API、动态组合和实例次数需要检查源码，未解析时明确标记 `needs-inspection`。
- `rendered`：每张可达原图对应的当前视口可见元素样式与根变量样本，包含字体、字号、颜色、圆角、间距、过渡和控件状态。每个状态最多40个元素、128个根变量；这不是全页元素穷举，也不代表鼠标、键盘、异步和错误状态已实际验证。

超过扫描文件/体积限制或 CSS 解析不完整时，产物为 `partial`。静态状态词只提供检查线索，不能把 `error` 字符串当作真实错误恢复成功。不同目录下同名组件按完整相对路径解析消费者，目录中的 CSS 文件不再误列为组件。

## 保留边界

OJO、Taste、Impeccable 的完整固定版本原包、引用、资源和许可证不删减。本次扩展的是证据与流程，不改写这些原始 Skill，不执行其中的安装器或全局 hooks，不自动授予 Foundation Approval 或用户 Accept。

已有 `foundation` 重试可为尚未规划的旧基线补充源码观察，此时标记 `unverified-legacy-capture`，不能反推旧截图和当前源码一致。已生成的阶段产物不可覆盖；源码变更应开始新一轮采集。

## 局部批准与执行范围

逐项决策支持“暂不纳入本轮约束”：候选保留 `observed` 状态、原始来源与证据，并记录 `deferred` 决策及原因。它既不成为批准规则，也不表示被弃用。未决项仍阻止保存，且版本至少需要一项可用的已批准 token、组件或模式；不可通过全部暂缓来绕过批准。

用户确认问题时填写的范围进入生成的执行任务书。它可以收窄模型建议，例如只增加长命令滚动提示、保留单行滚动及复制反馈；执行不得扩展到未确认的建议。批准设计规范与最终 Accept 是两次不同的判断，前者不自动填写后者。

# 官网 → 本地工作台

官网接入区先填写项目仓库目录、核心任务，以及项目内的 `DESIGN.md`、token 或组件源码相对路径（每行一项，可选择目录）。先在主工程运行 `pnpm workbench`；如果端口不同，展开“本地工作台地址”填写启动命令实际显示的 `/apps/designer/` 地址。只接受 HTTP loopback 地址。

点击“在本地工作台继续”会打开原有“连接项目”面板，预填这三项。确认后才读取本地文件并启动原有 onboard、采集、提取和首次诊断。不会把路径当作命令，不会批准 Foundation、确认候选或执行修改。已有 Agent 安装说明继续保留在官网折叠区。

官网“查看本次记录”复用同一交接 ID：任务仍在运行时展示原任务进度，结束后打开同一 run 的报告。任务失败也保留原始错误和恢复入口。官网不轮询本地接口、不上传源码；来源通过 URL fragment 交接，浏览器请求和 Referer 不携带该 fragment。官网仅在当前标签页的 sessionStorage 保留已提交数据；关闭标签页后请保留本地运行链接。更新本地工作台后再使用此入口。

本地将完整所选文件的相对路径、字节数和 SHA-256 写入现有 onboarding 配置，诊断上下文与人工确认后的执行任务书读取完整原文并校验哈希。上限为 12 个来源、128 个展开文件、单文件 256000 字节、合计 1000000 字节；不支持的类型、链接、越界、空目录、变化和超限会报错，不静默截断。执行前改动来源需重新审阅和生成计划。

项目源码属于来源绑定的参考资料，不能充当 Foundation 批准。继续沿用问题确认 → 计划 → 隔离执行 → 前后采集 → 独立复核 → 人工决定；执行和验收仍更新同一 run。Studio 内未导出的主题草稿不由此入口传送；已批准的 Foundation 仍走现有版本导入流程。完整 Skills 和发布守卫不变。

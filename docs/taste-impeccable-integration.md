## 如何使用偏好

首次接入仍只有项目目录和关键任务。可在“高级：预览与项目信息 → 设计方法与审美设置”选择方式、重点；已有完整项目配置也可声明 `designGuidance`：

```json
{
  "designGuidance": {
    "taste": "dials-v1",
    "intent": "layout",
    "dials": {
      "DESIGN_VARIANCE": 4,
      "MOTION_INTENSITY": 2,
      "VISUAL_DENSITY": 7
    }
  }
}
```

`taste`：`existing`（默认，新主入口与完整 App Screen，保持现有产品风格）、`app-screen`（显式应用界面与报告）、`public-page`（显式公开网站艺术方向）、`dials-v1`（完整原始三参数版）。`intent`：`polish`（默认）、`layout`、`animate`。三个整数范围1–10，留空沿用该 Skill 默认值；项目的已批准 Foundation 与确认范围始终优先。参数不授权自动扩大整改范围或新增动效。

Taste v2.1.4 主入口区分公开网站与 App Screen；工作台、编辑器和报告使用完整 `references/app-screens.md`，公开页面仍需显式选择。它采用方向抽取、真实素材和浏览器检查方法，**没有这三个数值参数**。三个参数仍保留在完整 v1 和 v2-experimental；本接入明确将数值偏好路由到 v1，拒绝错误地向当前 v2 写入 dials。默认不会给仪表盘套宣传网站的艺术风格。

## 首轮真实页面审阅（2026-10-14）

合并后的完整方法已用于 HappyClaw `90ae406` 的真实基线：桌面/手机整页、8 个区块和菜单打开/关闭/跳转快速开始，共21张原图。两次区域会话与一次独立跨区域会话进行了实际模型审阅，原图、来源哈希、方法快照、读取记录与结构化审阅均保留在本地运行 `2350de93`，没有拿安装或测试夹具冒充审美评估。重复发现保留原始批次记录，不能被当成11个独立缺陷或自动授权整改。

主要候选是重复卖点削弱层级、功能截图不易读取、手机架构图过小、快速开始长命令的读取/复制入口、文字/控件对比度与页面语义。这些判断支持下一轮确认范围，不证明改动收益或人工接受。上半区另有一个移动定位建议：复核后发现是懒加载图片引起采集滚动位置偏移，不能据此认定网站导航有缺陷。采集器现在在布局稳定后复核并有限重定位最后声明的 scroll-to，不重放点击或改变交互状态；到页面顶部/底部时保留合法的滚动边界。

本机 CLI 的全局默认模型名不被其当前账号接受。本轮只读审阅通过单次 GPT-5.5 覆盖运行，未改全局配置；工作台默认模型的账号兼容性需要单独确认。原始完整文件保留不意味着每个会话读完全部111个文件，读取日志与审阅结果才是本轮的实际应用证据。未运行 vendor launcher，未修改 HappyClaw，没有 after 对比、人工 Accept 或未记录的跨路由/动效/部署验收。

# #33 路由与交互规划

页面审阅中的“补充页面与交互范围”现在复用现有项目连接、受管理预览和任务队列。发现阶段只读取实际渲染的 DOM 与链接，不点击控件；浏览器阻止非 GET/HEAD/OPTIONS 请求及跨来源导航。它不会从截图猜组件或源码行号。初始页面、已有 routes 和用户补充路径进入同一有界队列；外部链接排除，失败、潜在副作用路径与达到上限的页面保留为缺口。

候选包括各设备的默认整页、具有唯一定位及 aria-controls/aria-expanded 的菜单展开/收起、有可核验目标的弹窗/Popover 打开与 Escape 关闭、可确定合成测试值的原生表单必填错误及修正恢复。表单只调用原生 reportValidity，不点击提交。自定义菜单、复杂字段、认证、服务端错误及重试需要明确声明动作、测试值和预期状态；可通过高级状态计划补充。所有候选与范围确认默认未勾选，候选不是确认的问题或复核结论。

确认后完整保留原有 capture plan，加入所选状态与每个路由/设备的默认整页原图，建立新 run 并关联父记录。旧截图、范围、执行与判断不重写；新 run 不携带旧 Finding/Evidence，不授权源码修改，不写人工判断。新基线继续走已有 Foundation→诊断→方向→范围确认→计划批准→隔离修改→匹配重采集→独立区域/跨区域 QA→人的决定。完整 Skills 和 OJO bundle 未修改。

采集契约新增唯一选择器点击/填入、按键、可见性或声明属性断言，以及原生表单有效性断言。操作顺序与核验结果写入 actionEvidence；不满足预期的状态保留 failed/error，不能作为成功截图。支持异步弹窗等待与关闭后 DOM 移除，导航最终 HTTP 错误不能算成功。可读标题用于页面状态选择，原始稳定 ID 继续用于匹配。

规划结果绑定父 run、干净源码提交、配置与原采集计划摘要以及发现期间稳定的入口响应指纹。忙碌、跨记录、源码/配置漂移、未知候选、冲突 ID 和空范围均拒绝。计划文件摘要在配置加载、排队、采集前后及后续操作再次核对，修改计划必须建立新记录。发现和采集均停止自己启动的预览，返回 404 的已占用端口也不能借用。关闭/重开面板可恢复持久化候选，恢复时禁止与新发现竞态提交。生成目录不触发服务重启。

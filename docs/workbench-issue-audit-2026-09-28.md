# 工作台与开放 Issue 执行核对 · 2026-09-28

本轮核对全部 13 个开放 Issue。以下是代码与验证现状，不把接口存在、测试样例或草稿保存当作真实业务验收。

## 本轮已经补上的能力

- 创作任务：图片、参考图修改、HTML、Slides 通过本机 Codex CLI 执行；PNG/HTML 校验后提供预览、下载和放回画布。真实调用分别验证了 HTML、图片、改图和两页 Slides。
- 持久任务：排队、运行、结果、失败、取消、服务重启后的中断状态。刷新界面不会丢任务；不会自动重复执行中断的源码修改。
- 项目接入：输入仓库、预览、启动方式，或导入已有配置。记录仓库 commit 和配置指纹；旧审阅关联项目后可启动新审阅。无法确定源码版本的旧截图不直接驱动修改。
- 修改源码：人工确认范围后建立新 run，在隔离 Git worktree 中修改，重新采集并检查桌面和移动端，产出 diff。预览端口被占用时拒绝把其他服务当作修改结果，可从采集阶段重试。
- 人工流程：诊断产生的问题可经确认转成带证据引用的执行范围；独立视觉复核导入、Accept/Reject 经原 Harness 闸门写入，不自动接受。
- 项目经验：同仓库历史、带 judgment / evidenceHash 的候选原则、显式批准或拒绝、不可覆盖的决定版本；不自动修改全局技能或当前设计基础。
- 设计基础：工作台可运行已有 token / 品牌 / 组件提取，导出候选结果；现有产品也可在规划之前导入人工批准的完整 Foundation 快照。
- Token 提取修复：深色主题独有 token 不再崩溃，声明空格不再漏记来源；增加文件/行号、消费者、别名、循环与未解析引用，冲突保留供审阅。
- 回归保障：新增任务服务、项目经验、诊断转计划与 token 边界测试；Skill Result 保留输入/实现/契约指纹和仓库 commit，并防止 handler 覆盖来源元数据；新增 Windows/Linux CI。

HTML 真实调用结果在主工作台验证放回画布；图片生成与参考图改色产出实际 PNG；Slides 产出独立 HTML。QA 输出明确标注测试用途，不计作 HappyClaw 业务验收。创作草稿也不等于受 Foundation 约束的正式页面生成。

HappyClaw 已核实本地仓库来源并建立当前 commit `70a9980` 的新审阅 `67c44c53`，完成桌面/移动基线和诊断；未擅自替用户确认问题或修改其源码。旧 run `06dabc2c` 已关联该项目，可从工作台发起新审阅。

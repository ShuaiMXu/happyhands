# HappyClaw：批准后的限定修改验证

用户明确确认现有规范作为本轮约束，只修改长命令的滚动提示，不强制折行。此授权不等于接受最终页面，也不批准模型提出的其他页面改造。

## Harness 修复

- 设计基础支持“暂不纳入本轮约束”。保留候选的 observed 状态、原值、来源、证据和暂缓原因；不能作为 approved 规则使用。未决项仍阻止保存，全部暂缓也不能生成可用批准版本。
- 用户确认问题时的范围进入执行任务书，并以有长度限制的 JSON 字符串表达。任务书和确认记录分别以哈希绑定到计划，执行上下文建立前和 agent 启动前均校验；改动后必须重新生成计划。
- 画布请求先保存来源，再生成带完整性绑定的计划，避免后追加任务书导致哈希失效。
- 完整 OJO、Taste、Impeccable 和项目 Skills 未删改。批准快照、原图、失败日志和专项验证保留在本地，不提交私有证据。

## 真实流程与失败恢复

源代码基线为 HappyClaw `1036381`，内容树与主线 `fe3a1ab` 一致。原始 `572a739a` 接收本轮批准后，首次隔离执行因本机 Codex 初始化权限失败，未修改目标代码，保留失败记录。

新记录 `ae1309c0` 完成实际隔离修改，但首个实现将提示叠在命令上。前后原图和独立视觉复核发现遮挡，独立代码审阅还发现初始 HTML 未隐藏提示，JavaScript 不可用时会误显示。该轮没有接受或合并。独立复核另提出页面横移推断，需要结合实际滚动状态的 DOM 数据核验，不能只凭模型文字改动全局布局。

后续修正保留单行横向滚动和复制反馈，将提示置于命令下方；只有溢出时预留提示行，滚到末尾隐藏文字而保持高度，无溢出或 JavaScript 未执行时不显示提示。以正常桌面和手机为主验收，已有 200% 辅助观察不作为改版依据。

专项记录通过已有原图绑定附件带入视觉复核。本轮初始配置未声明 verificationChecks，因此没有补写虚假的结构化 verificationEvidence；专项脚本另外校验实际源码与 after 提取快照一致、运行前后完整仓库指纹一致，并保留这一限制。需要自动专项门禁的项目，应在首次采集前配置 verificationChecks。

自动视觉复核最终记录为 fail，提出“末尾滚动导致页面横移”。该判断没有被静默改写。真实方向键测试记录 scrollLeft/max=106/106、scrollX=0、无页面溢出、页头左边距始终16px，提示行高度23.796875px不变；返回起点后提示恢复。另一轮独立证据审阅将该项判为 unsupported / false-positive，未发现可执行的页面回归。代码合并依据独立代码/原图审阅和这轮争议复核，不冒充原自动报告 pass，也不替用户最终 Accept。

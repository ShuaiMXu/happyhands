# 工作台 UI / UX Skill 审阅

日期：2026-09-30

范围：审阅报告、画布、代码改动、设计方向四个工作台视图

方法：项目内 OJO 规范 + `frontend-design` 反模式检查 + `audit` 全面审阅

## 结论

当前工作台已经形成统一的左侧导航、顶部工具栏和内容容器，品牌、颜色、圆角与交互基调基本一致。它没有落入霓虹渐变、玻璃拟态、随机装饰或游戏化仪表盘等常见 AI 界面套路，适合作为工具型产品继续收敛。

当前版本仍不适合把“设计方向”作为任意审阅记录的源码修改入口。页面虽然会把 `case=run:<id>` 带到地址栏和其他视图，但方向数据、保存任务和实际执行仍固定绑定 HappyClaw 的静态评审。用户从另一条审阅记录进入时，可能看到并执行不属于当前项目的建议。这是发布阻断项。

审阅结果：**1 个 Critical、4 个 High、4 个 Medium**。在 Critical 修复前，工作台可以用于本地查看与画布调整，但不应允许从任意运行记录直接执行源码修改。

## Critical

### 1. 设计方向与当前审阅记录没有真正绑定

- **位置**：`apps/designer/directions/main.js`、`packages/workbench/directions.js`、`packages/workbench/direction-execution.js`
- **证据**：方向页只用 `case` 参数拼接导航链接，却始终读取固定的 `review.json`；浏览器缓存键和 POST 请求都使用该固定评审的 `data.id`。服务端也只校验并保存同一份静态评审，执行器进一步把项目限制为 `happyclaw-site`。
- **影响**：从 `case=run:<id>` 进入方向页时，页面看起来属于当前审阅记录，实际显示、保存和执行的却可能是另一个项目的方向。用户可能批准错误范围并修改错误源码。
- **最小修复**：让方向数据由当前运行记录、项目绑定和证据摘要生成，保存任务时同时固化 `runId`、仓库、源提交与证据摘要；执行前再次核对。如果当前运行记录不支持方向生成，应显示明确空状态并禁止保存和执行。
- **建议 Skill**：`harden`，之后使用 `normalize` 复核状态呈现。

## High

### 2. 核心画布出现 tldraw 生产许可证水印

- **位置**：`apps/designer/cowart/editor.jsx:156`
- **证据**：当前画布可见 “Get a license for production”；代码只从 `VITE_TLDRAW_LICENSE_KEY` 注入许可证，本地环境未配置有效值。
- **影响**：核心编辑界面直接暴露第三方生产水印，影响品牌完整性，也说明分发条件尚未闭合。
- **最小修复**：在生产构建中配置有效许可证；没有许可证时明确标记开发模式，或在分发版本中暂时关闭该编辑器入口。

### 3. 核心信息大量使用 9–11px 字号

- **位置**：`apps/designer/workbench-system.css`、`apps/designer/studio.css`、`apps/designer/directions/style.css`
- **证据**：共享顶部栏、运行选择器、本地状态和 eyebrow 使用 10px；画布的阶段标签、底部提示、状态栏、批注元信息等仍包含 9–11px 文本。
- **影响**：审阅状态和证据元信息在高 DPI、缩放或视力较弱的场景下难以读取，层级主要依赖“缩小文字”而不是间距、字重和颜色。
- **最小修复**：收敛到受控字号阶梯：正文不低于 14px，控件与元信息不低于 12px，纯辅助说明不低于 11px；在 125%、150%、200% 缩放下复核。
- **建议 Skill**：`normalize`。

### 4. 多个交互控件没有达到 44×44 的触控目标

- **位置**：`apps/designer/workbench-system.css`、`apps/designer/directions/style.css`、`apps/designer/studio.css`
- **证据**：语言选择器和运行选择器高度 38px，共享按钮 42px，方向决策按钮 40px，画布部分工具按钮只有 32–40px。
- **影响**：手机、触控板和触屏设备上容易误触；主要决策动作也缺乏一致的操作密度。
- **最小修复**：移动端把所有按钮、选择器和图标控件提升到至少 44×44；桌面仅在 `pointer: fine` 时保留紧凑尺寸。
- **建议 Skill**：`adapt`。

### 5. 390px 宽度下主导航依赖无提示的横向滚动

- **位置**：`apps/designer/workbench-system.css` 的 620px 媒体查询
- **证据**：窄屏隐藏 Logo 后，导航容器开启横向滚动，同时四个视图的最小宽度固定为 460px。
- **影响**：用户可能看不到“设计方向”等主要入口，也没有视觉提示说明导航还能横向滑动。
- **最小修复**：在窄屏使用四等分标签或底部标签栏，保留图标与短标签，让所有一级视图无需横向滚动即可发现。
- **建议 Skill**：`adapt`。

## Medium

### 6. 英文界面的无障碍名称仍是中文

- **位置**：`apps/designer/index.html:15-31,79-91`、`apps/designer/directions/index.html:13-71`
- **证据**：工作台导航、视图导航、语言选择器、画布工具、工作流和任务列表的 `aria-label`、`title` 与部分占位文案写死为中文。
- **影响**：可见界面切换到英文后，屏幕阅读器仍读出中文，重新形成用户之前指出的中英文混搭。
- **最小修复**：让可访问名称、标题、占位文案和状态提示使用同一份语言映射；评审证据原文继续保留原语言。
- **建议 Skill**：`harden`。

### 7. 共享设计系统仍被三套 CSS 重复定义

### 8. 画布首开资源较重，需要真实测量后优化

- **位置**：Cowart/tldraw 的独立构建产物与字体资源
- **证据**：编辑器已按路由动态加载，这是正确做法；当前构建中编辑器 chunk 约 1.86 MB，另有多份约 150 KB 的字体文件。
- **影响**：旧设备或冷启动时可能出现画布进入延迟。当前没有运行时测量，因此这是风险，不是已确认的性能故障。
- **最小修复**：记录画布冷启动、可交互时间和主线程阻塞，再决定是否裁剪字体、延后非必要模块或在用户悬停/聚焦画布入口时预取。
- **建议 Skill**：`optimize`。

### 9. 工具型工作台的首屏仍偏向营销页层级

- **位置**：设计方向和审阅报告首屏
- **证据**：巨大标题、说明段、推荐卡和流程条占据首屏上半部，真正需要判断的方向卡或审阅内容被推到下方；多个等权白色卡片继续增加扫描负担。
- **影响**：用户进入工作台后不能立即完成“看证据—做决定”的核心任务，尤其在笔记本高度下需要先滚动。
- **最小修复**：把大标题压缩为页面标题与一行状态，把 AI 推荐做成紧凑摘要，让第一项可决策内容进入首屏；保留现有品牌语言和整体外壳。
- **建议 Skill**：`distill`。

## 已通过的检查

- 四个视图已经使用同一套左侧导航、顶部栏和内容宽度，桌面端对齐明显改善。
- 颜色和视觉语言克制，没有无依据的渐变、霓虹、玻璃拟态或装饰性图表。
- 导航使用统一 SVG 图标，没有把 emoji 当作功能图标。
- `focus-visible` 有明确描边，`prefers-reduced-motion` 会关闭动画与平滑滚动。
- 截图和证据来自真实运行；缺少数据时使用明确空状态，没有伪造结果。
- 原始证据保留原语言是合理行为，界面语言应独立切换。
- Cowart 已动态加载，没有把大型编辑器塞进所有视图的初始包。

## 处理顺序

1. 修复方向任务与运行记录、项目、源提交的绑定，并阻止错误范围执行。
2. 处理 tldraw 分发许可或关闭无许可的生产入口。
3. 统一字号与触控目标，完成真实窄屏复测。
4. 把所有可访问名称纳入中英文语言系统。
5. 合并重复 CSS，建立单一 shell/token 来源。
6. 压缩报告与方向页首屏，再以真实任务测试决策效率。
7. 对画布做性能测量后再决定资源优化范围。

## 审阅边界

本报告依据当前源码与本地桌面页面进行审阅。移动端问题来自响应式源码检查，尚未包含实体手机测试；性能项来自构建产物体积，尚未包含运行时指标。按照 `audit` Skill 的要求，本轮只记录问题，没有在审阅过程中修改产品代码。

# 本地工作台与线上官网

## 当前使用方式（2026-10-18）

`happyhands` 是本地工作台与 Harness 工程；`happyhands-site` 是独立部署的公开官网。官网部署不提供本地仓库读写或代理托管。

```sh
pnpm install --frozen-lockfile
pnpm workbench
```

打开 `http://127.0.0.1:4190/apps/designer/`。需要 Node.js 22.15+、pnpm 11.19+ 和 Chrome 或 Edge；代理整改及模型复核还需要已配置的对应 CLI。工作台先连接项目目录和关键任务，再检查采集范围。诊断后选择设计方向、确认问题与修改计划，再进入隔离执行、重新采集、独立视觉复核及人工接受/拒绝。计划准备或确认问题不等于代码已修改，模型通过不等于用户接受。

本地服务支持受控写入运行记录、Foundation 治理和截图批注。原图是证据，不是可直接编辑的设计稿；批注仍须经过同一条修改与复核流程。失败、缺失状态与未批准候选保持可见。打开示例不会自动接入对应仓库。

`pnpm harness export --run .harness/runs/RUN_ID` 发布可静态查看的证据到 `public/runs`；静态导出不提供本地执行接口。独立改动 CLI 记录后需重新导出以更新静态副本。开发服务使用仓库的 Vite 本地插件，不应将 `dist` 静态站点当作可写工作台。

当前验收缺口见 [发布待办](next-steps.md)。下方保留当时的迁移决策和验证，日期与功能边界只描述历史版本，不作为当前使用指引。

## Cowart 批注画布接入（2026-09-28）

画布的定位调整为当前界面的修改草稿。默认只展示同一状态/配置的最新可达截图，优先修改后截图；通过“当前界面”选择其他状态。原有前后截图、问题、结构评估与人工判断仍在审阅报告，代码补丁仍有独立入口。

接入范围是 Cowart 0.1.28 的箭头批注工具及其标签编辑逻辑，基于 tldraw 5.1.1 嵌入工作台；源码位于 `apps/designer/cowart/annotation.js`，保留 Cowart MIT 版权文件 `LICENSE.Cowart`。不是把 Codex 原生 Cowart widget 原样嵌入网页，也没有宣称已接通其图像生成、HTML/Slides 生成或自动修改项目源码。未引入上游分析统计模块。

- 选择、抓手、箭头批注、文字、画笔、撤销/重做、适应视图；原始截图锁定为底图。
- 草稿通过仅限本地的工作台服务写入 `.harness/cowart/<run>/<phase-state-config-fingerprint>/canvas.json`。保存画布快照、文字要求和来源指纹，不改写导出记录。
- 以截图 SHA-256 区分不同证据版本；版本号拒绝多标签页过期写入。读取失败不会创建空白覆盖，保存失败保留编辑器并提供备份导出。
- “生成修改任务”保存带原始来源、快照及批注的 `request-<uuid>.json`，下载指向该文件的 Markdown 修改任务；状态明确为 draft，不直接启动代理、不修改项目代码，也不绕过已有隔离执行/视觉复核/人工判断流程。

- Vite dev 与 preview 均注册本地服务；纯静态部署不具备此持久化接口，不能当作已支持的在线编辑服务。

## 本地执行服务（2026-09-28 后续实现）

“项目与任务”可以连接仓库/预览/启动程序，或导入原有 project.json，启动基线采集与基于真实 DOM 的诊断。关联随审阅项目保存在本地，不以 creative-os 作为默认修改对象。配置变化、仓库版本变化、旧截图没有 commit 或尚未应用的 after 工作区，都要求重新建立审阅基线。

画布操作可选择草稿、图片、改图、HTML、Slides 或修改当前项目源码。源码入口要求显式确认范围，执行在隔离 worktree，完成后重采集和 evaluate；仍等待独立视觉复核与人工判断，不自动 push/merge/deploy。重新采集失败可在“项目与任务”重试，原执行不会重跑。

任务与作品位于 `.harness/workbench-jobs`，项目关联在 `.harness/workbench-projects`，接入配置在 `.harness/projects`，项目经验在 `.harness/project-memory`。日志不通过静态 run 导出。生成 HTML 的服务响应施加 sandbox 与 CSP，限制其访问工作台和网络；PNG 校验签名、尺寸和路径。

任务取消会终止 CLI 进程树；采集步骤受自身超时限制，取消后不会保存新的采集阶段。服务正常关闭会请求取消，重启将残留运行记录标记为 interrupted，不自动再次执行。运行中避免修改服务配置以免开发服务器重启；刷新页面不影响任务。

完整验收与限制见 `workbench-issue-audit-2026-09-28.md`。

## 阶段主路径

页面审阅、报告和代码改动顶部提供同一个“本阶段下一步”。它由服务端当前阶段决定，执行中的任务会暂时禁用；任务结束后先读取新证据，再启用下一动作。选择问题、确认修改范围、阅读完整计划及接受/拒绝都需要明确操作；独立复核失败只能拒绝。Foundation 主动作打开原有逐项决定和版本批准表单，不替人批准。

失败重连保留原采集计划、路由和启动环境。仅有导出记录而没有本地原始运行时，连接原项目会建立当前源码的新审阅，不能直接写入旧证据。结构检查后仍需要独立视觉复核与人工判断。首次生成的待渲染控制记录不代表已采集界面。

验证控制流程可运行 `pnpm test:review-actions:browser`，需要本地 Chrome；可用 `BROWSER_CHANNEL` 选择浏览器，`REVIEW_ACTION_EVIDENCE` 指定截图和结果目录。此脚本使用明确标记的修改/采集/QA 夹具，不对真实产品给出通过结论。可选 `REVIEW_ACTION_REAL_RUN` 指向已有真实 Harness run，验证它在三个视图与两个设备的历史回放。

## 2026-10-13 接入与统一主路径

首次接入默认填写项目目录与关键任务。Vite/Astro 的 npm/pnpm dev 脚本可只读识别并预填本地预览；未知方式通过高级设置填写，已有配置文件可继续导入。自动配置不会安装依赖，也不会修改目标源码。Astro 自动预览使用 --ignore-lock 保持受管理前台进程，禁止自动后台脚本；原配置、环境和声明的采集计划在同一仓库重连时保留。

接入自动完成采集、Foundation 提取与规则诊断，然后进入当前页面审阅。先查看前三条有来源的候选，其余和原始数据按需展开；已知检查提供可编辑的说明，不冒充模型完整任务诊断或已确认问题。四步进度为连接项目、选择问题、确认修改、查看结果。

确认范围自动生成完整计划，不执行改动。阅读并明确同意后，才使用共用的修改→重采集→结构检查→独立 QA 流程，最后单独记录接受/拒绝及理由。高级面板用于连接、任务进度、外部独立复核导入及项目经验；Foundation 进入已有结构化治理界面。旧画布请求和设计方向转为计划输入，保留来源，执行必须回主路径批准。完整 OJO、Skills、证据闸门与人工决定保留。

## 补充项目设计系统

在项目源码中维护 `DESIGN.md`、样式 token 和组件实现，并提交这些修改。工作台不会将观察到的值自动批准为设计规范。

1. 打开已连接项目的「审阅报告 → 设计基础与版本治理」。
2. 展开「如何补充或更新设计系统」，点击「按更新后的规范开始新审阅」。这会重新采集并提取当前源码，保留旧运行与旧版证据；需要可运行的预览和干净的 Git 工作区。
3. 检查新候选的来源、token 和组件状态，逐项选择批准、替换或弃用，填写必要理由，再显式确认设计基础版本。进入修改规划后的旧版本仍保持冻结。

示例和只读导出没有这个写入口，需要先连接原项目。此入口读取项目文件，不支持直接导入外部设计稿链接或图片。

首次页面诊断会在工作台采集与设计基础提取后启动只读 Codex 会话，读取完整 OJO、Taste/App Screen、Impeccable 与本项目层级审阅规则。模型候选进入原有问题确认流程，不自动批准设计基础、执行修改或给出验收分数。报告展示模型状态、缺失证据和失败原因；确认问题前可以重试。当前一次诊断最多使用 96 张原始截图，每批最多 24 张；超限或缺图会明确失败，不能通过丢弃截图伪造完整覆盖。需要本机 Codex CLI 已配置可用模型；失败时只保留明确标记的规则候选。
